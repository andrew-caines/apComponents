# Icons

The icon set, its sizes, and the decorative-versus-labelled contract.

The set below is deliberately small — it grows one icon at a time, alongside
the component that needs it, so nothing ships unused.

## The set

<div className="grid">
  {Object.keys(ICON_PATHS).map((name) => (
    <div key={name} className="row">
      <Icon name={name} size="lg" />
      <span className="mono">{name}</span>
    </div>
  ))}
</div>

## Sizes

Sizes are `em`-based, so an icon inherits the type size of its context.
Colour comes from `currentColor` — there is no colour prop to keep in sync.

<div className="mono">size=xs … 2xl</div>
<div className="row">
  {['xs', 'sm', 'md', 'lg', 'xl', '2xl'].map((size) => (
    <div key={size} style={{ textAlign: 'center' }}>
      <Icon name="info" size={size} />
      <div className="mono">{size}</div>
    </div>
  ))}
</div>

## Decorative or labelled, never both

Without a `label` an icon is hidden from assistive technology, which is right
whenever text beside it already says the same thing. With one it becomes an
image with an accessible name. Announcing a state twice is noise, not
redundancy.

<div className="stack">
  <div className="row">
    <Icon name="check" />
    <span>Saved — the icon here is decorative, the word carries the meaning</span>
  </div>
  <div className="row">
    <Icon name="check" label="Saved" />
    <span className="mono">label="Saved" — announced, because nothing else says it</span>
  </div>
</div>
