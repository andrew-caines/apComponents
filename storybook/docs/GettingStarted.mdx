# Getting started

apComponents is a React component library with a build-time theme: the
colour tokens, fonts and motion live in plain stylesheets, so a page paints
correctly from the server response before any JavaScript runs. You vendor it
into your app as a git submodule, add one Vite plugin, load three stylesheets,
and wrap your tree in one provider. This page takes you from nothing to a
rendered, accessible form, and every code sample on it is quoted from a
fixture app that the library's own test gates build and run.

## Add the submodule

Add the repository to your app as a submodule.

```sh
git submodule add https://github.com/andrew-caines/apComponents vendor/apComponents
```

Then depend on the two packages you use directly through `file:` paths. The
sample below comes from a fixture app inside this repository, so its paths are
relative to that fixture. Yours are relative to your app's `package.json`:
with the submodule at `vendor/apComponents` beside it, as in the command
above, they are `file:vendor/apComponents/packages/react` and
`file:vendor/apComponents/packages/vite`.

Import the plugin in your `vite.config.ts`, then add it to the `plugins` inside

<Source language="ts" code={extractRegion(ssrVite, 'vite')} />

`apComponents()` configures Vite for the library:

- **vanilla-extract**, which the components' styles are written in.
- **`ssr.noExternal` and `optimizeDeps.exclude`** for the `@ap/*` packages only. Their source is compiled by your build rather than loaded as-is, so an SSR build runs the style transform over it and the dev server does not pre-bundle it.
- **One copy of React.** Base UI's packages that import React are compiled into your SSR build, `use-sync-external-store` is replaced with an ES module that re-exports React's own hook, `react` and `react-dom` are deduped, and `@ap/react`'s dependencies are pre-bundled for the dev server. React itself is never bundled: every React import resolves to your app's copy, in development and production, whether or not the submodule has its own `node_modules`.
- **`build.cssTarget`** set to `AP_CSS_TARGET` (Chrome and Edge 120, Firefox 114, Safari 16.4), so the minifier does not rewrite `:dir()` into `:lang()` and break right-to-left styling. It does this only if you set neither `build.target` nor `build.cssTarget`; if you set either, your value wins.
- **A build warning**, from a small `ap-components:rtl-check` plugin, if a `:dir()` rule still ends up lowered to `:lang()` in your built CSS.

That plugin list is the whole of your apComponents setup. Your app adds
nothing else: no `ssr.noExternal`, no `resolve.dedupe`, no alias and no extra
dependency. CI proves it with an app outside this repository whose config is
exactly the two lines above, in development and production, with the submodule
installed and not installed.

## Load the CSS

Import three stylesheets once, at the root of your app.

<Source language="tsx" code={extractRegion(rootTsx, 'css')} />

`fonts.css` declares the typefaces, `theme.css` defines the colour, spacing and
type tokens every component reads, and `motion.css` defines the animation
custom properties. `motion.css` is load-bearing: components such as Dialog and
Spinner animate through `animation: var(--ap-motion-*)`, which resolves to
nothing, silently, without it.

## Wrap and render

<Source language="tsx" code={extractRegion(startTsx, 'start')} />

`ApProvider` composes the theme, locale, icon and notification providers in one
element. `Field` derives the label and description wiring for its control, so
you do not pass ids around yourself. The `action` of `/subscribe` is
illustrative; point it at your own endpoint.

The form submits before hydration, because the controls are uncontrolled: the
browser owns their values, so a submission made before your JavaScript loads
still works. To change the palette, read
[Theming](?path=/docs/foundations-theming--docs).

## Dates and Temporal

The date formatters, and `useFormatter` from `@ap/react/hooks`, accept
[Temporal](https://tc39.es/proposal-temporal/docs/) values alongside `Date`.
The library does not ship Temporal: use the browser's, or add
`@js-temporal/polyfill` to your app.

<Source language="tsx" code={extractRegion(datesTsx, 'dates')} />

Each value renders by what it means:

- A `PlainDate`, such as a hire date, is the same day for every reader, on
  the server and in the browser. So is a date-only string like `'1990-05-12'`.
- A `ZonedDateTime` renders in its own zone: a 9:00 meeting in Tokyo reads
  9:00 everywhere. To show it in the reader's zone, format `zdt.toInstant()`, which follows
  the same rule as an `Instant` below. Use `withTimeZone(zone)` only for a fixed
  zone that the server knows too.
- An `Instant` is a moment, like a `Date`. It renders in UTC on the server and
  in the reader's zone after hydration.

Wrap each one in `<time dateTime={isoFor(value)}>` so the value stays
machine-readable.
